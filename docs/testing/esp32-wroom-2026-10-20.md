# ESP32-WROOM-32 Firmware Hardware Test Evidence

Date: 2026-10-20
Target: ESP32-WROOM DevKit
Example: `examples/ESP32_WROOM32_VIA_BLE`
Candidate state: current working tree; source candidate has 8 modified files and is not yet a release commit

## PASS

- [x] Native WSL tests passed with warnings-as-errors: `protocol_test`, `esp32_ble_hid_test`, `esp32_ble_transport_test`, `esp32_shared_server_test`, `esp32_nvs_test`, and `esp32_gpio_test`. Each printed `All tests passed!`; aggregate exit `0`.
- [x] Arduino CLI compile passed with `esp32:esp32:esp32`. Flash usage: 625899/1310720 (47%). RAM: 39660/327680 (12%).
- [x] Upload to COM39 passed. esptool identified ESP32-D0WDQ6 revision 1.0; image regions reported verified hashes.
- [x] Serial boot passed at 115200: NVS capacity 4096, NimBLE initialization, shared server, HID service, FF60/FF61/FF62 service, advertising, protocol begin, keyboard begin, ready.
- [x] BLE scan found address with HID service `1812` and AirVIA VIA service `FF60`.
- [x] GATT read of FF62 returned firmware version `1` and name `AirVIA WROOM32`.
- [x] GATT command `0x01` returned a fixed 32-byte response reporting VIA `0x000D`.
- [x] Read-only protocol synchronization passed: 3 layers, 180 keymap bytes / 90 words, encoder values, layout options, macro count and macro size.
- [x] Reversible keymap persistence passed: first key original `0x0010`; temporary `0x0004` acknowledged/read; restored `0x0010`; commit `09 02`; reconnect readback remained `0x0010`.

Direct BLE checks used temporary user-installed Python Bleak tooling. It is not a firmware/library dependency.

## Reported wiring failure

- [ ] User connected matrix pins directly and reported no key response. This was not independently reproduced during this run.
- [ ] The example config is `5x6`, `kColToRow`, rows `{4,5,12,13,14}`, columns `{15,16,17,18,21,22}`.
- [ ] First matrix validation must use a real switch, one diode per switch, and column pull-up resistors. GPIO direct shorts are not a valid production matrix test.
- [ ] Avoid boot-sensitive GPIO5, GPIO12, and GPIO15 during the first wiring test. Start with R0/GPIO4 and C1/GPIO16.

## Remaining firmware tests

1. Single-switch matrix test: GPIO4 ↔ GPIO16 with 10 kΩ GPIO16-to-3V3 pull-up and column-to-row diode orientation.
2. Add GPIO17, GPIO18, GPIO21, GPIO22 one at a time and verify column mapping.
3. Exercise all rows/columns, debounce, release, modifiers, layer keys, 6KRO, rollover and stuck-key recovery.
4. Test physical encoder on GPIO33/GPIO32. Current WROOM loop consumes and discards `encDelta`; encoder HID action is not accepted.
5. Test hard power-cycle persistence after the keymap round-trip.
6. Rebuild with CI-pinned ESP32 core `3.1.0`; local compile used `3.3.0`.
7. Review and commit the 8-file candidate as a known SHA before release use.
8. Run soak, reconnect, invalid packet, storage failure, and recovery acceptance from the master checklist.

## Release boundary

This evidence proves WROOM compile, upload, boot, BLE advertisement, VIA GATT protocol, synchronization, and reversible keymap persistence. It does not prove physical matrix typing, encoder action, lighting, power-loss durability, long-run stability, or production readiness.
